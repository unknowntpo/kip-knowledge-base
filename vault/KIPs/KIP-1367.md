## Summary

Message types in Kafka are keyed by a unique apiKey to uniquely identify them. These include all RPC types used by the brokers and controllers, metadata records stored in the KRaft metadata log and the data stored by coordinators.

Kafka contributors regularly introduce new message types in order to evolve the Kafka protocol. However, contributors run the risk of adopting an apiKey that is subsequently claimed by another proposal while they prototype their work. This is a problem shared by other Apache projects as well [0]

A workaround for this is for contributors to use a large value for apiKey which is currently unused and is unlikely to be used in the near future. apiKey is represented as a short with non-negative range from [0, 32767]. This KIP proposes formalising the reservation of the last 1024 values, i.e. [31744, 32767] for private use, ensuring future protocol changes would take the reserved values into account.
