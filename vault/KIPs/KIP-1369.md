## Summary

Kafka's null-safety and thread-safety contracts live only in Javadoc, so nothing enforces them. A method that starts returning null, or a field read without its lock, compiles clean and breaks at runtime. Concurrency is also affected: Kafka is heavily threaded, and the lock-ownership reasoning behind many classes lives only in javadoc.

This proposal annotates Kafka's public API with existing contract annotations. A typed @Nullable or @GuardedBy("lock") beats a Javadoc sentence: it is uniform, greppable, shows in the IDE and generated docs, and tools read it without parsing prose. These concepts are already duplicated across the ecosystem, so rather than issue Kafka's own we can reuse the CLASS-retained SpotBugs and JSR-305 annotations, which the build's existing tools already recognise.

Kafka annotates its public API with existing annotations, added compileOnly via spotbugs-annotations (which also brings jsr305). All are @Retention(CLASS): read by build tooling and dropped by the JVM, so there is no runtime footprint. compileOnly keeps the jars out of the shadow jar and the published runtime dependencies.
