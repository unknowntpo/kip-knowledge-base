## Summary

We did deprecate the "old Processor API" of Kafka Streams and replaced it with the "new Processor API" to improve type safety via . However, we missed to update KTable.transformValues which is still using the old Processor API (ValueTransformerWithKeySupplier and ValueTransformerWithKey). This prevented us from completely removing all classes of the old Processor API in Apache Kafka 4.0 release. To complete removing the old Processor API in Apache Kafka 5.0, we need to deprecate KTable.transformValues and replace it with a new method which uses the new Processor API.

Unfortunately, we also introduced a backward incompatibility bug in the newly added KStream.processValues implementation (cf ASF JIRA5aa69414-a9e9-3523-82ec-879b028fb15bKAFKA-19668). To address this backward incompatibility, we propose to also deprecate KStreams.processValues methods, and replace with a backward compatible alternative.

@Deprecated KTable transformValues(final ValueTransformerWithKeySupplier transformerSupplier, final String... stateStoreNames);
