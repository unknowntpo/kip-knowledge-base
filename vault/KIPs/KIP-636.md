## Summary

KIP-482 added support optional tagged fields. Tagged fields require no space when they're omitted from RPCs using flexible versions. A 16 bit ErrorCode is used in the vast majority of RPCs and will normally have value 0 (NONE). Similarly ErrorMessage will in these cases be null, but still requires a byte to store the string length.

By changing these mandatory fields to tagged fields we can save two bytes for every error code and 1 byte for every message. Since some RPCs have error codes and messages for each batched entity in a response the saving can be more significant across a whole message.

When the error code is nonzero a tagged field will require 4 bytes (tag and size each 1 byte varints and the 16 bit value requires two bytes), rather than the 2 bytes needed for an int16. Similarly non-null error messages will require 2 bytes (tag and size each 1 byte varints) more than the usual serialization of the string.
